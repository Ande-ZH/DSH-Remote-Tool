# 当前实现与验证

本次实现将 Magpie 部署接入远端 Host 启动流程，并整理模块边界和界面。

- `src/runtime/magpie.cjs`：检测和复用现有网关；准备官方固定版本终端版；支持预装路径、端口和关闭自动部署；用户服务或独立进程启动；健康检查和部分失败结果。
- `src/services.mjs`：组合设备与 Magpie 服务，设备存储不再依赖模型功能。内部目标查询不对 HTTP 调用方开放。
- `dist/host.cjs`：自包含远端启动器，构建后通过 SSH 上传，保留旧数据位置和 CLI 入口。
- `src/ui/`：使用官方 Button、Input、Checkbox、Modal 和语义颜色；控件样式随插件加载和释放。
- 共享外观：沿用远端 DSH 的 `ui-theme` 配置与事件机制，本地 Desktop 插件安装和配置仍独立。
- 按项目要求，自动部署不执行 SHA-256 校验。
- `dsh-remote install`：通过 DSH 自带命令安装插件；持久保留归档，支持指定命令路径和 profile。GitHub 归档可直接通过 npm/npx 使用，无需源码构建。
- 发布配置：版本 `0.3.0`，提供构建/测试/真实安装 CI 与手动 OIDC 发布工作流；npmjs.org 首次发布等待用户稍后登录。

## 已执行验证

验证环境：Linux amd64、Node.js 24.21.0、DSH 0.2.2-rc.1、Magpie 0.1.4539。

| 验证 | 结果 |
| --- | --- |
| 构建与单元/运行时测试 | 9 项通过，包含真实 Magpie 缓存安装、启动和重复复用 |
| 空白目录 Magpie 下载 | 从官方发布地址下载并启动成功，再次连接复用网关 |
| SSH 端到端 | 两个客户端共享工作区、运行任务和持久会话；Host 重启后恢复；远端插件安装/启停/卸载通过 |
| 共享外观 | A 修改主题和字号，B 读取相同配置；Host 重启后恢复；真实浏览器 B 自动接收 A 的主题变更 |
| Magpie 端到端 | 原生模型停用/恢复、同步、真实网关对话、保留其他提供方、拒绝旧 Host instance、清空受管提供方通过 |
| 安装包 | npm 安装 CLI → `dsh-remote install --profile web` → 删除 CLI 副本 → 真实 DSH 插件加载、认证接口与客户端模块发布通过；归档持续可用 |
| 浏览器交互 | 官方 Web Host 内设备添加/移除和确认弹窗可操作，无页面脚本异常；深浅主题切换已验证 |

运行命令沿用 README。真实 Magpie 用例需设置 `DSH_E2E_MAGPIE_BIN`；加 `DSH_E2E_MAGPIE_DOWNLOAD=1` 可检查空白目录下载。SSH 测试可额外设置 `DSH_E2E_PNPM` 使用预装 pnpm，测试内隔离用户服务以避免影响测试机的 systemd 实例。

## 验证边界与后续工作

- ARM64 发布资产已配置，尚未在 ARM64 主机运行。Windows Desktop 内嵌页面需要 Windows 实机验证。
- Docker 部署继续沿用网关浏览与模型同步路径，现有网关复用已用 HTTP fixture 检查；本次未运行真实 Docker 容器。
- 第三方外观插件各自的自定义设置是否共享取决于其 Host settings 接入。当前验证覆盖 DSH 内置外观，具体第三方插件需单独适配与验收。
- 自动升级/回退、独立修复入口、完整部署进度展示仍按实施规划后续推进。当前安装失败保留 DSH 工作区，重新连接重试。
